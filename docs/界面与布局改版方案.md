# 页集：界面与布局改版方案

日期：2026-11-19。状态：核心改版已实施；个人常用、最近访问和资源历史趋势仍为后续项。

## 1. 设计方向

以“AI 应用门户”为用户侧定位，以“平台控制台”为管理员侧定位。沿用同一个系统、同一个登录入口，以及平台超级管理员和普通用户两种角色。

用户侧强调找到应用、打开应用；管理员侧强调找到账号、掌握用量、处理异常。统一品牌、主题和交互规范，分别组织导航与内容。保留左侧、顶部、平铺三种租户布局，以及框架内显示、框架外打开两种方式。

## 2. 改版前的问题

- 大卡片单位面积容纳的入口较少，长期积累后会产生较长滚动距离。
- 现有平铺缺少菜单搜索、分类筛选和分页，重名末级菜单也不容易区分。
- 平台管理把租户、用户统计、资源和日志放在一个大面板内，缺少整体概览和明确的处理路径。
- 用户表同时展示多项计数与配额，列数较多；详情、统计和编辑需要分层。
- 目前进入平台管理会同时读取租户、用户、资源和审计数据；相关列表主要一次返回。改版需要同步处理后端分页与按需读取。
- 当前资源接口提供主机即时数据，尚不能直接展示历史趋势。

## 3. 用户侧顶部与导航

顶部约 64px：左侧品牌与当前空间名称，右侧保留 MCP 接入、工作台设置、主题和账号菜单。存储详情收进账号菜单和空间设置，接近配额时显示轻量提示。

左侧或顶部导航只展示租户菜单。工作空间、页面管理、菜单管理、上传记录、空间设置继续通过顶部工作台入口访问；MCP 继续保持顶部独立按钮。

平铺首页的搜索与筛选放在内容区顶部，不额外复制一套全局搜索。主体使用全部可用宽度，桌面边距 24～32px；左侧布局保留约 224px 菜单区和 24px 内容间距。

## 4. 平铺首页：默认采用紧凑链接目录

### 4.1 目录结构

首页由以下三部分构成：

1. 简洁标题与入口总数。
2. 搜索、分类筛选、排序和视图切换工具栏。
3. 网站链接目录与底部分页。

首页不混排平台统计、广告式横幅或其他页面内容。空空间显示上传和 MCP 接入引导；存在内容后收起引导。

### 4.2 两种展示方式

| 方式 | 展示规则 | 用途 |
| --- | --- | --- |
| 紧凑链接，默认 | 桌面多列、手机单列；浅底或细分隔线，悬停高亮 | 日常浏览应用入口 |
| 列表 | 一行一个入口，名称、所属路径、页面数量和打开操作清晰对齐 | 数量较多、名称较长或重名较多的空间 |

紧凑链接每项由 28～32px 应用标识、名称和打开箭头构成。首字标识作为默认，无文件夹图标；次要信息仅在必要时展示。普通桌面约 3～5 列，按可用宽度调整，入口高度通常约 72～88px，内容较多时自然增高。

菜单名称按 20 个汉字完整展示，允许两行换行；更长名称继续自适应，不通过省略号隐藏。名称优先分配宽度，箭头与标识保持小尺寸。整项可点击，键盘焦点清晰可见。

平铺仍然只展示原有结构的末级菜单，不展开二、三级。分类筛选可复用原有一级分类，只改变当前结果，不修改菜单结构。分类较多时放进可搜索选择器，工具栏不无限堆叠分类标签。

### 4.3 查找与排序

- 搜索可展示的菜单名称与其关联页面名称；页面名称命中时明确显示匹配页面入口，避免要求用户再次盲选。
- 搜索结果显示完整所属路径，尤其用于区分同名末级菜单。
- 默认按租户配置的菜单顺序排列；名称和最近更新排序由用户主动选择。
- 搜索、分类、排序和分页可以组合，明确显示结果数量和清除筛选入口。
- 进入内容后返回目录，恢复原搜索条件、页码和滚动位置；更改搜索、分类或排序时从第一页开始。
- 隐藏菜单及隐藏父级下的菜单不出现在门户浏览和搜索结果中；管理功能仍按原权限访问这些记录。

“常用”和“最近访问”建议作为后续个人筛选入口，避免额外叠加一大片内容。常用标记与访问记录属于个人偏好，不改变租户菜单顺序。

### 4.4 大量内容的加载规则

- 建议紧凑目录每页 48 项，列表每页 50 项，通过服务端分页返回。
- 搜索与筛选在服务端覆盖全部授权结果，不能只过滤当前页。
- 请求带稳定排序，搜索输入适当防抖；较早返回的请求不得覆盖更新的查询。
- 不一次加载全部 HTML，不提前创建 iframe，不自动请求全部页面截图。
- 租户级导航按需读取元数据；后续根据实际性能再增加缓存或虚拟滚动。

## 5. 应用打开与返回

- 单页面菜单：按空间配置直接进入内容。
- 多页面菜单：进入独立列表，只展示该菜单自身页面；该列表同样支持搜索与分页。
- 框架内显示：保留简洁顶部、页面标题和返回入口，HTML 占据主要空间，平铺目录不与内容混排。
- 框架外打开：新标签页展示已授权内容，原标签页保留目录及浏览位置。
- 刷新分享链接、返回列表和浏览器前进后退具有明确行为，筛选状态可写入 URL；页面授权仍从现有接口获取，敏感凭证不写入 URL 状态参数。
- 继续保留租户权限校验与独立内容源隔离。

## 6. 平台管理：独立的控制台布局

### 6.1 入口与框架

超级管理员从“工作台设置 → 平台管理”进入控制台。顶部明确标识“平台管理”，提供“返回我的空间”。不新增登录入口，不增加角色。

控制台使用专门的管理导航，替换租户导航：平台概览、租户管理、用户管理、上传任务、资源监控、审计日志。桌面建议左侧约 200px 导航、右侧全宽内容，手机折叠为抽屉。该导航仅用于管理区，不改变用户空间的左侧、顶部或平铺偏好。

### 6.2 页面职责

| 页面 | 主要内容 | 常用后续操作 |
| --- | --- | --- |
| 平台概览 | 租户数、用户数、已发布页面数、逻辑存储用量；配额接近上限、失败任务和排队情况 | 点击指标进入已筛选的列表 |
| 租户管理 | 租户名称、状态、用户数、页面数、存储用量/配额、操作 | 查看详情、修改配额、停用/恢复 |
| 用户管理 | 用户名/手机号、所属租户、状态、页面数、已用/账号配额、操作 | 查看详情、修改配额、调整归属与状态 |
| 上传任务 | 上传者、租户、文件名、状态、提交时间、处理结果 | 筛选失败或排队任务，查看错误原因 |
| 资源监控 | 主机 CPU、内存、磁盘、数据库大小、版本文件逻辑用量、任务队列 | 查看采集范围、更新时间及资源说明 |
| 审计日志 | 操作者、所属租户、动作、对象、时间和结果 | 按账号、租户、动作、时间筛选，展开详情 |

所有列表提供搜索、状态筛选、分页和稳定排序。用户和任务列表支持租户筛选；用户搜索覆盖用户名和手机号。进入哪个管理页面，再读取对应数据。

### 6.3 表格与详情

列表优先保留约 6～7 组主要信息，主名称与操作列固定。存储列用“已用 / 配额 + 进度条”，临近上限再强化颜色。

上传次数、失败次数、版本数、最近上传时间等信息放进用户详情。租户详情组织账号、用量、近期上传和状态信息。常规编辑使用右侧抽屉，信息较多的详情使用独立详情页；返回列表时保留筛选和页码。

手机号、状态、配额、归属的编辑明确区分。停用、删除和调整租户归属显示具体影响，删除说明数据保留规则；缩小配额不得删除已有内容。

### 6.4 统计与资源口径

- 账号默认存储配额继续为 1 GB，上传同时受账号配额与租户总配额约束。
- 账号累计上传量、版本逻辑用量，与当前租户所拥有页面的用量分别命名；用户调整归属后，避免将两者误认为同一统计口径。
- 统计明确区分当前页面数、累计上传次数、历史版本数和保留文件用量。
- 资源页面注明当前主机、采集时间和刷新状态；主机磁盘、数据库物理大小、页面版本逻辑用量分开展示。
- 用户级先展示可归属的存储与上传数据。页面在浏览器运行时的 CPU、内存不能作为服务器侧精确用户用量展示。
- 历史趋势需要先增加定时采集和时间序列保存，再展示曲线；无采集数据时明确展示即时值或暂无数据。

## 7. 视觉与交互规范

深色主题使用深海军蓝背景、略亮的内容面板，青蓝作为主色，紫色作为少量强调色。浅色主题使用蓝灰白背景、白色内容区、清晰的蓝色操作入口。

科技感集中在品牌、选中状态、细边框光感和短动效。后台表格保持清晰、紧凑、稳定。正文字号建议 14～16px，重要名称 15～16px，次要说明避免过小；对比度满足可读性要求。

按钮、输入框、表格、标签和抽屉统一圆角、间距和状态颜色。入口悬停与页面切换动效约 150～200ms，支持系统减少动态效果设置。

加载时显示骨架或进度；无结果、空空间、网络失败、上传失败、权限失效分别提供清晰提示和可执行操作。保存成功提示及时消失，不长期覆盖页面内容。

## 8. 需要同步补充的能力

### 本轮优先落实

- 平铺紧凑链接目录与列表视图、20 字名称完整显示、重名路径提示。
- 目录与管理列表的搜索、筛选、服务端分页和浏览状态恢复。
- 控制台导航、概览、租户/用户详情及配额呈现。
- 上传失败与排队的可见入口、审计筛选、按页面读取数据。
- 深浅主题及宽屏、笔记本、手机的统一适配。

### 后续按实际使用增加

- 个人常用入口和最近访问。
- 应用自定义图标；默认首字标识已经可以使用，不增加上传图标的前置步骤。
- 主机和任务历史趋势、定时汇总与告警通知。
- 批量归档、历史文件清理和统计导出；应先确定保留期限与操作影响。

## 9. 技术实施与范围

复用 Vue 3、TypeScript、Element Plus 和现有 FastAPI/PostgreSQL，不因视觉改版更换框架或新增一套登录。对目录和管理列表增加分页、筛选及详情接口；查询始终执行对应的租户或超级管理员权限校验，SQL 索引根据实际查询验证。

租户共同设置：菜单名称、层级、顺序、可见性、导航布局、页面打开方式。个人偏好：深浅主题、目录展示方式；后续个人常用和访问记录同样独立保存。搜索和分页属于当前浏览状态。平台控制台布局固定，不受租户导航设置影响。

改版保留现有页面、菜单关联、HTML/ZIP 上传、MCP 自动建菜单、账号配额及 RLS 隔离。新增的目录搜索、常用记录、历史监控等能力应在实施时明确迁移和测试范围，不能当作现有功能已经具备。

## 10. 验收与实施顺序

1. 先完成统一主题、顶部工具栏、紧凑目录与列表视图。
2. 接入服务端查询和分页，验证搜索、浏览状态、应用打开与返回。
3. 重组平台控制台、管理列表和详情，补齐筛选与按需加载。
4. 评估真实使用数据后增加个人常用和资源历史趋势。

验收目标包含 20、100、1000、5000 个入口的布局、搜索、分页与渲染。此次已对少量示例和 5000 条入口进行实际测试；数据量验证不等同于并发容量验收。1440px 和 2560px 屏幕充分利用宽度，390px 窄屏无横向溢出，20 字中文名称完整显示，进入内容与返回目录恢复浏览状态。

管理端验证按账号或租户查找、用量与配额可辨识、调整后正确反馈；所有新增查询执行权限与隔离检查。实施与测试记录见《验证记录》。

## 11. 本轮实施结果

已实施统一深浅主题、紧凑目录/列表、分类与名称搜索、服务端分页、URL 浏览状态恢复、独立控制台及按页读取、账号与租户详情/配额抽屉、任务筛选与审计筛选、即时资源展示。菜单管理和上传记录也已改用服务端搜索分页。旧版 API 保留，网页目录与管理使用新增列表 API，MCP 兼容原接口。

实际使用独立测试租户的 5000 条入口验证后端分页、搜索与浏览器渲染，每页只渲染 48 项；测试入口结束后清理。导航和菜单编辑仍读取完整菜单元数据，避免改动原有三级层级及选择逻辑；目录分类选择器使用虚拟列表。未将本轮功能验证视作并发容量验收。

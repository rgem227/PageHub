# 文件管理与空间清理

更新日期：2026-11-20。

## 使用入口

- 普通用户：顶部“工作台设置 → 文件管理”。
- 页面卡片“更多 → 管理文件”、上传记录“管理文件”、版本记录底部按钮，可直接筛选该页面的所有版本；刷新浏览器保留页面筛选。
- 空间设置的“管理文件 / 清理空间”入口。
- 超级管理员：“平台管理 → 文件管理”，支持跨租户和上传者筛选。

## 展示与统计

界面包含空间概览、菜单目录、上传文件和清理任务。目录大小包含所有下级菜单和所有保留版本；“已下架页面”概览是筛选入口，不是额外一份文件，不重复累计。

上传列表每行对应一次上传，显示原始文件名、所属页面、版本编号、当前/历史标识、菜单路径、挂接状态、占用大小、文件数量、文件状态和上传时间/上传者。包括成功、失败、处理中和文件已删除的历史记录，支持搜索、状态/上传者筛选、按大小或时间排序及服务端分页。

点击“文件清单”可查看该版本的 HTML、图片、样式、脚本等内部文件，按目录及文件名筛选。每个内部目录显示含下级的总大小。现有版本由后台补齐清单，新上传时直接记录；扫描异常显示原因，可重新扫描。

空间以保留版本的文件字节总量统计，不是 ZIP 压缩包大小，也不等同于磁盘块、数据库文件或备份占用。处理后的原始上传暂存不作为可下载原包永久保留。未生成页面版本的上传记录不代表一个已发布文件包；原始暂存及未入库残留仍沿用上传清理与运维检查机制。

## 删除规则

| 操作 | 页面访问 | 文件与空间 |
| --- | --- | --- |
| 下架页面 | 停止访问 | 保留全部版本，继续占用配额 |
| 删除历史版本 | 当前页面继续访问 | 删除选定完整版本及资源，完成后释放空间 |
| 彻底删除页面及文件 | 提交后立即停止访问 | 删除该页面全部保留版本，完成后释放空间 |

当前版本不能单独删除。可以先将另一保留版本设为当前，再删除原版本。批量删除只允许选择未进入清理流程的历史版本，一次最多 100 个，页面列表每页 50 个。

整页删除确认框显示版本数、文件数和预计释放空间。确认期间版本集合发生变化时拒绝提交，需重新确认。页面关联菜单不会自动删除；文件清理完成后解除已彻底删除页面的菜单关联，空菜单可再通过菜单管理删除。

删除按完整版本执行，不开放单独删除 ZIP 内某张图片、CSS 或 JS。彻底删除无法通过平台恢复；上传记录、版本元数据和审计继续保留，已删除版本不会恢复到可用列表，版本编号也不会被复用。

## 任务与空间一致性

清理任务有等待删除、删除中、删除失败、已完成四种状态。失败可手动重试；文件未全部删除完成前不归还配额，部分删除失败也保守保留原计费大小。正常完成后同时更新原上传账号和文件所属租户的逻辑用量；上传者后来更换租户也不会把额度归还给其他人。

等待删除、正在删除或删除失败的版本均不能继续通过内容网关访问，也不能回滚或重新设为当前。包含未完成版本清理任务的页面，需要先完成或重试该任务，再提交整页删除。

独立 worker 优先处理清理任务，再处理上传和旧版本清单。处理进程异常退出后，超过 5 分钟的任务租约可由 worker 接续，删除操作幂等。清理前验证完整的租户/页面/版本目录，不接受客户端传入存储路径。

## 数据与部署

`backend/schema.sql` 增加版本文件清单、稳定版本编号、删除标记、页面清理标记和 `file_deletions` 任务表，任务表采用与现有业务相同的 PostgreSQL RLS。已有数据保留。升级使用现有 `backend/bootstrap.py` 应用幂等迁移、授权，并重启 API、内容服务和 worker；本机已完成。

本地存储使用受目录边界校验的删除。S3 兼容存储在永久清理时读取 bucket 版本控制状态；启用或暂停版本控制时，会删除对应目录内所有对象版本及删除标记。除原有对象读取与上传权限外，需允许 `s3:GetBucketVersioning`、`s3:ListBucketVersions`、`s3:DeleteObjectVersion`、`s3:ListBucket`、`s3:DeleteObject`。对象锁、保留策略或权限限制导致删除失败时，任务失败且不释放配额。

没有新增按期限自动删除或备份清理策略。实际 S3、对象锁和生产权限仍需在目标环境联调；本机物理删除使用独立测试租户验证。

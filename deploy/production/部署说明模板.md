# PageHub 正式环境

部署日期：2026-11-22。当前服务已启动并可从局域网访问。运行组件：PostgreSQL 18.4、Python 3.12.12、Nginx 1.28.0、RustFS 1.0.6。

## 访问与账号

- 工作台：`https://__LAN_IP__:51730`
- 独立页面内容入口：`https://__LAN_IP__:51731`
- 初始管理员：用户名 `admin`；随机临时密码保存在 `D:\PageHub\credentials\admin-initial.txt`。
- 首次登录必须修改密码。确认新密码可用后删除 `admin-initial.txt`。
- HTTPS 使用本机签发的内部证书。首次在其他电脑访问前，将 `D:\PageHub\certs\pagehub-trust.cer` 导入“受信任的根证书颁发机构”；只向受信任的 PageHub 客户端分发此证书。

## 端口

| 端口 | 监听范围 | 用途 |
| --- | --- | --- |
| 51730 | 局域网 | HTTPS 工作台、API 和 MCP，经 Nginx 转发 |
| 51731 | 局域网 | HTTPS 隔离页面内容入口 |
| 55432 | 本机 | PageHub 独立 PostgreSQL 18 实例 |
| 58000 | 本机 | FastAPI 与 MCP 后端 |
| 58011 | 本机 | 页面内容授权服务 |
| 59000 | 本机 | RustFS S3 API |

所有端口均为五位数。只有 51730 和 51731 供局域网客户端访问，Windows 防火墙仅允许本地子网来源；数据库、API、内容服务和对象存储只监听本机回环地址。

## 启停与日志

在 PowerShell 中执行：

```powershell
Set-Location D:\PageHub
.\scripts\start.ps1
.\scripts\stop.ps1
```

Windows 服务 `PageHubPostgreSQL` 会随系统启动。Windows 重启后，还需执行 `start.ps1` 启动 RustFS、PageHub API、内容服务、worker 和 Nginx。日志保存在 `D:\PageHub\logs`。

## 数据与隔离

- 生产数据库为独立集群：`D:\PageHub\postgres\data`，端口 `55432`，数据库 `pagehub_prod`，应用账号 `pagehub_prod_app`。
- 页面对象保存在 `D:\PageHub\s3\data`；应用只连接私有 bucket `pagehub-prod`。
- 初始化只创建 schema、平台空间和一个 `admin`，没有导入开发/测试用户、上传记录或页面。
- PostgreSQL 超级用户密码在 `D:\PageHub\credentials\postgres-superuser.txt`，只用于数据库维护。
- `.env` 含应用密钥、数据库口令和 S3 凭证。不要发送或提交；备份时一并做加密保护。
- 定期备份 PostgreSQL 数据库和 `s3\data`。数据库与对象数据必须配套恢复。

## 已知限制

- MinIO 社区版已归档且官方停止分发二进制，因此本环境使用 RustFS `1.0.6` 提供 S3 兼容接口；未启用对象存储管理控制台。PageHub 使用 S3 API，不依赖控制台。
- 当前为 `SMS_MODE=temporary`：不发送短信，验证码通过 HTTPS API 响应并显示在注册页，仅供可信局域网临时使用；它不能验证手机号所有权。接入短信服务商后改为 `SMS_MODE=provider`，发送接口路径 `/api/auth/sms` 保持不变。不要将临时验证码模式暴露到公网。
- HTTPS 证书绑定当前 LAN IP `__LAN_IP__`，有效期 825 天。IP 变更或证书到期时需更新证书、`.env` 和 Nginx 内容策略配置，并将新 CA 证书分发到客户端。
- 当前仅开放局域网 HTTPS 入口，没有公网域名和受信任的公网证书。不要直接映射到公网。
- API 配置为 4 个进程 worker；这不是 1000 并发容量验收。本次只做部署/健康检查，没有执行压力测试。
